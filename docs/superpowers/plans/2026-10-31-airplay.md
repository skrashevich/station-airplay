# Station AirPlay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A pure Go AirPlay 2 buffered-audio receiver using the firmware's common ALSA default output.

**Architecture:** Adapt goplay2's pairing, RTSP and timing protocol; replace native audio/codec layers with go-aac and a managed aplay process. Keep model-independent device configuration and reversible installation.

**Tech Stack:** Go 1.26+, go-aac, pure Go HomeKit/crypto/plist/mDNS libraries, firmware aplay.

**Spec:** docs/superpowers/specs/2026-10-31-airplay-design.md

## Global Constraints

- CGO_ENABLED=0; no native codec or audio libraries added.
- Output ALSA PCM default; no model-specific branches or global mixer writes.
- Existing aplay is explicitly approved; package Linux ARM64 and ARMv7.
- No system clock changes, OTA changes or Quasar interception. The later user-authorized inittab autostart update permits a temporary root remount, restored after the atomic edit; it adds no init script.
- Real iPhone verification is distinct from synthetic protocol/audio tests.

## Review Focus

- Pairing encryption transition preserves buffered bytes and isolates connections.
- Flush/pause/reconnect cannot play stale samples or leak child processes.
- Negotiated codec/sample rate and advertised features agree with implementation.
- TCP truncation/authentication failures cannot panic or allocate unbounded memory.
- PTP loss or blocked output cannot hang shutdown or steal an existing session.
