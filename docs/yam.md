# Установка через YAM

Нужны root-доступ, установленный [YAM v2](https://github.com/nyakokitsu/yam)
и прошивка с glibc/libasound, поддерживаемая station-airplay. Старый YAM с
пакетами `.yap` не подходит. Обновите менеджер: пакет использует executable-файлы
в `share/`, права которых старые версии YAM теряли. Формат и ограничения:
[упаковка YAM](https://github.com/nyakokitsu/yam/blob/main/docs/PACKAGING.md).

## Совместимые колонки

Поддерживаются все Яндекс Станции на Linux с glibc/ALSA и root-доступом;
Android-модели исключены. Выберите ID своего
профиля YAM; это ID менеджера, он не всегда совпадает с названием модели.

| Модель | Профиль | Приёмник |
| --- | --- | --- |
| Лайт | `yandexmicro` | ARM64 |
| Лайт 2 | `plum` (старый alias `yandexplum`) | ARM64 |
| Мини 1 / Мини 2 | `yandexmini` / `yandexmini_2` | ARM64 |
| Мини 3 / Мини 3 Про | `bergamot` / `pickle` | ARM64 |
| Миди | `cucumber` | ARM64 |
| Станция 2 | `yandexmidi` | ARM64 |
| Стрит | `mango` | ARMv7 |
| Станция 3 | `orion` | ARM64 |

Это список собираемых пакетов, а не подтверждение воспроизведения на каждой
модели. Требования к прошивке и результаты аппаратных проверок находятся в
[README](../README.md#требования-и-совместимость) и [validation.md](validation.md).
Макс (включая вариант с Zigbee, профиль `yandexstation_2`) и Станция первого
поколения на штатной прошивке (`yandexstation`) работают на Android и не
поддерживаются. См. [описание Макс](https://hackalice.me/devices/station-max/) и
[первого поколения](https://hackalice.me/devices/station-gen1/).
Профили хаба `saturn` и сторонней колонки `jbl_link_music` также в выпуск не входят.

## Установка по имени из реестра

Команды выполняются **на колонке**, в SSH/ADB shell. Добавьте официальный
реестр, если он ещё не настроен, и установите пакет. Перед установкой остановите
старую автономную службу или встроенный AirPlay в Quasar Bridge, чтобы освободить
порты приёмника:

```sh
yam registry add official https://repo.yse.wtf/v2 \
  --key ed25519:5Rz8F47uftWVU5kLgWYhprkEZ4rpP2kecUge/a7KQas=
yam install skrashevich/station-airplay
station-airplay -check
station-airplay-service status
```

Для конкретной версии используйте `yam install skrashevich/station-airplay@0.1.2`.
Ключ и URL приведены из [документации YAM](https://github.com/nyakokitsu/yam#использование).

## Установка из GitHub Releases

Например, для Миди:

```sh
curl -fL https://github.com/skrashevich/station-airplay/releases/download/v0.1.2/install-yam.sh -o /tmp/install-station-airplay-yam.sh
sh /tmp/install-station-airplay-yam.sh cucumber v0.1.2
station-airplay -check
station-airplay-service status
```

При отсутствии `curl` скачайте скрипт через `wget -O`. Установщик загружает
`.yampkg` и `SHA256SUMS` того же релиза, проверяет SHA-256 и вызывает `yam install`.
Нужны `curl` или `wget`, `sha256sum`, HTTPS-доступ к GitHub. Хеш из того же
HTTPS-релиза проверяет целостность загрузки; подпись реестра в этом режиме не используется.
Проверка `-check` не воспроизводит звук; она проверяет интерфейс и библиотеки вывода.

Можно скачать пакет на ПК со [страницы релиза](https://github.com/skrashevich/station-airplay/releases/tag/v0.1.2),
сверить его SHA-256 с `SHA256SUMS`, передать по ADB/SSH и установить локально:

```sh
yam install --yes /tmp/station-airplay-0.1.2-cucumber.yampkg
yam doctor
yam service list
station-airplay-service status
```

YAM проверяет профиль и архитектуру. Не переименовывайте пакет другого профиля:
например, `cucumber` и `yandexmidi` используют один ARM64 binary, но разные манифесты.

## Автозапуск, управление и состояние

На поддерживаемой колонке установка сразу запускает приёмник и создаёт отдельный
`/etc/init.d/S99station-airplay-yam` для запуска после перезагрузки. Скрипт
использует стабильную публичную ссылку YAM, поэтому обновление пакета не требует
смены пути в init-скрипте. Существующий init-скрипт другого YAM-корня или
посторонний файл с тем же именем не перезаписывается: установка завершится
ошибкой, пока владелец не освободит этот путь. При установке вне колонки (`yam --root` на ПК)
активация пропускается. Hook распознаёт колонку по
`/system/vendor/quasar/quasar.cfg`; для создания init-скрипта нужен root-доступ.
Если корневая ФС доступна только для чтения, установочный hook временно
перемонтирует её в режим записи и возвращает режим чтения. При загрузке
перемонтирование не выполняется. Настройки и службы аудио прошивки не меняются.

Команды доступны через `$YAM_ROOT/bin`, обычно `/data/yam/bin`:

```sh
station-airplay-service status
station-airplay-service stop
station-airplay-service start
station-airplay-service restart
station-airplay-service disable  # остановить и отключить автозапуск
station-airplay-service enable   # включить автозапуск и запустить
```

`status` показывает состояние супервизора; готовность AirPlay и ошибки
приёмника смотрите в логах. Супервизор повторяет запуск после ошибки с паузой
две секунды, ожидает завершения при SIGTERM до десяти секунд и лишь затем
принудительно завершает зависший дочерний процесс. Повторный `start` не создаёт
второй экземпляр. На колонке супервизор создаёт отдельную сессию через
`setsid` (или applet BusyBox), чтобы отключение ADB shell не завершало службу.
Отключение через `disable` сохраняется при обновлении пакета;
ручной `start` остаётся доступен. `stop` останавливает текущий экземпляр,
сохраняя включённый автозапуск на следующую загрузку.

Команда `station-airplay` запускает приёмник на переднем плане и передаёт ему
все аргументы CLI. Сначала выполните `station-airplay-service stop`, если нужен
ручной запуск с собственными параметрами, например
`station-airplay -name 'Моя Станция AirPlay'`. При ручном запуске на переднем
плане остановка выполняется через Ctrl+C. `station-airplay -check` проверяет
интерфейс и библиотеки вывода без воспроизведения звука.

По умолчанию состояние сопряжения и приватный кэш PCM находятся в
`$YAM_ROOT/var/skrashevich.station-airplay`, обычно
`/data/yam/var/skrashevich.station-airplay`. Корень определяется по установленному
пакету, поэтому поддерживается и нестандартное размещение YAM. Для ручного запуска
launcher учитывает явно заданный `YAM_VAR`: тогда состояние находится в
`$YAM_VAR/skrashevich.station-airplay`.

Служба запускает launcher без переопределений `YAM_ROOT`/`YAM_VAR`, сохраняя
совместимость со старыми установками. Если в основном каталоге нет `identity.json`,
но он существует в `var/skrashevich.station-airplay` рядом с каталогом YAM,
используется прежний каталог. Например, для YAM в `/data/yam` старое сопряжение
из `/data/var/skrashevich.station-airplay/identity.json` сохраняется при установке,
обновлении и перезагрузке. Идентичность не переносится и не перезаписывается;
если она уже есть в основном каталоге, используется основной каталог.
Новые приватные каталоги доступны только владельцу.

Логи службы и приёмника: `$YAM_ROOT/var/skrashevich.station-airplay/service.log`
и `receiver.log`. PID супервизора и запрос остановки находятся в
`$YAM_ROOT/run/skrashevich.station-airplay/service`. Пакет также объявляет
службу `skrashevich/station-airplay/receiver` в YAM; текущий YAM хранит эту
декларацию без собственного супервизора, поэтому запуском управляет команда
`station-airplay-service`.

Перед установкой остановите старую автономную службу
`/data/opt/station-airplay/service stop` или встроенный AirPlay в Quasar Bridge,
если он включён: экземпляры используют одни порты. Чтобы вручную использовать
сопряжение автономной установки, остановите службу YAM и укажите прежний каталог:

```sh
station-airplay-service stop
station-airplay -data-dir /data/opt/station-airplay/state
```

При обновлении hook останавливает прежний приёмник и запускает текущую версию.
Если автозапуск отключён, служба, вручную запущенная через
`station-airplay-service start`, также перезапускается на новую версию.
Остановленная служба остаётся остановленной; флаг отключения сохраняется.
Для удаления:

```sh
station-airplay-service disable
yam remove skrashevich/station-airplay
```

Оставшийся `/etc/init.d/S99station-airplay-yam` можно удалить отдельно командой
`rm -f /etc/init.d/S99station-airplay-yam`. Если `/` доступен только для чтения,
перед удалением init-скрипта временно перемонтируйте его в запись и затем верните
режим чтения. В текущем YAM нет hook удаления: если удалить пакет без
предварительной остановки, супервизор обнаружит
исчезновение публичного executable и завершит свой приёмник. Оставшийся
init-скрипт безопасно пропускает запуск, когда команда пакета отсутствует.
Каталог состояния сохраняется; его отдельное удаление отменяет сопряжение.

## Откуда берутся описание и список колонок

Текст задаётся полем `description` в `packaging/yam/yam.yaml.in`.
`scripts/build-yam.py` подставляет версию и профиль, а upstream `yam-publish pack`
записывает описание в `MANIFEST.yaml` внутри `.yampkg`. При публикации реестр
читает эти метаданные и показывает описание пакета в каталоге.

Профили и архитектуры перечислены в `packaging/yam/targets.tsv`. На каждый
профиль собирается отдельный архив. Веб-каталог реестра объединяет профили
артефактов **всех опубликованных версий**, а установщик проверяет наличие
артефакта именно выбранной версии. Поэтому удаление профиля из нового выпуска
само по себе не убирает его из списка на сайте: для этого нужно также убрать
ошибочный старый артефакт средствами реестра. Профили менеджера сами по себе
не подтверждают совместимость приложения.
Для исправления описания/списка уже опубликованной версии выпускается новая
версия пакета. Порядок подписанной публикации описан в [releases.md](releases.md).
